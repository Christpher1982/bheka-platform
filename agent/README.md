# Bheka Keystroke Capture Agent (proof-of-concept)

## Consent & authorization

This is a proof-of-concept endpoint agent used to test Bheka's own detection
pipeline end to end: capture -> ingest -> v0 rule engine -> Detections page
in the console.

**Only run this on a machine you own or are explicitly authorized to
monitor.** It captures every keystroke typed while running and sends batches
of that text to the Bheka API server. Do not install it on a device
belonging to someone else without their informed consent.

## What it does

- Hooks keyboard input with `pynput` (no admin rights needed on Windows in
  normal cases).
- Buffers captured text and a keystroke counter, and best-effort captures
  the active window title with `pygetwindow`.
- Every ~10 seconds, or whenever 50 keystrokes have been buffered (whichever
  comes first), POSTs one batch to:

  ```
  POST {BHEKA_API_URL}/api/v1/agent/events
  Header: X-Agent-Token: {AGENT_TOKEN}
  Body:
  {
    "tenantSlug": "eride-technologies",
    "siteId": "<site-uuid>",
    "subjectUserId": "<user-uuid>",
    "sourceAgentId": "<auto-generated-or-set>",
    "eventType": "keystroke_batch",
    "occurredAt": "2026-08-01T20:30:00Z",
    "metadata": {
      "keystrokeCount": 37,
      "activeWindowTitle": "Gmail - Compose",
      "capturedText": "hello this is a test..."
    }
  }
  ```

  The API server runs a v0 rule engine synchronously on ingest (sensitive
  keyword match, off-hours activity, high keystroke volume) and may create a
  Detection, which then shows up on the console's Detections page.

## Setup

```
pip install -r requirements.txt
```

## Required environment variables

| Variable | Description |
|---|---|
| `BHEKA_API_URL` | e.g. `http://192.168.1.50:8080` — use the LAN IP of the machine running the API server. `localhost` will NOT work if this agent runs on a different PC than the API server. |
| `AGENT_TOKEN` | Shared secret matching `AGENT_INGEST_TOKEN` set on the API server. |
| `SITE_ID` | The seeded site UUID (e.g. the "Head Office" site under tenant `eride-technologies`). |
| `SUBJECT_USER_ID` | The user UUID this activity is attributed to (e.g. the seeded admin user `admin@eride-technologies.test`). |

## Optional environment variables

| Variable | Default |
|---|---|
| `TENANT_SLUG` | `eride-technologies` |
| `SOURCE_AGENT_ID` | Random UUID generated once at startup |

You can find `SITE_ID` / `SUBJECT_USER_ID` from your seeded dev data (check
`scripts/seed-dev.ts` output, or query them from the console / API once
logged in as `admin@eride-technologies.test`).

## Run

**Windows (cmd.exe):**
```
set BHEKA_API_URL=http://192.168.1.50:8080
set AGENT_TOKEN=your-shared-secret
set SITE_ID=<site-uuid>
set SUBJECT_USER_ID=<user-uuid>
python bheka_keystroke_agent.py
```

**PowerShell:**
```
$env:BHEKA_API_URL="http://192.168.1.50:8080"
$env:AGENT_TOKEN="your-shared-secret"
$env:SITE_ID="<site-uuid>"
$env:SUBJECT_USER_ID="<user-uuid>"
python bheka_keystroke_agent.py
```

**bash / WSL:**
```
export BHEKA_API_URL="http://192.168.1.50:8080"
export AGENT_TOKEN="your-shared-secret"
export SITE_ID="<site-uuid>"
export SUBJECT_USER_ID="<user-uuid>"
python3 bheka_keystroke_agent.py
```

## What you'll see

On start:
```
Bheka keystroke agent started. Reporting to http://192.168.1.50:8080 every
~10s or 50 keystrokes. Tenant=eride-technologies Site=<id> Subject=<id>
```

On each send:
```
[12:04:31] Sent 37 keystrokes (window: 'Gmail - Compose') -> HTTP 201.
Detection created: True (id=abcd-1234). Preview: "hello this is a test..."
```

On error:
```
[12:04:41] ERROR sending batch: ConnectionError(...)
If BHEKA_API_URL points to localhost but you're running this on a different
PC than the API server, use the API server machine's LAN IP address instead.
```

Stop with Ctrl+C — any remaining buffered text is flushed and sent before exit.
