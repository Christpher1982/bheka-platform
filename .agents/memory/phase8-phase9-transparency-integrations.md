- GET /v1/webhooks — list; secretHash NEVER included in SELECT

- PATCH /v1/webhooks/:webhookId — rotateSecret: true generates a new secret and returns it once
- DELETE /v1/webhooks/:webhookId — soft-deactivate; audited

## Key design rules (Phases 8 + 9)

### BhekaSession has NO roles field
req.session does not carry role names. Any route that needs to check roles must either:
(a) Use requireRole() middleware (blocks non-holders), or
(b) Query the DB via a hasElevatedRole() helper pattern (for conditional behavior, not blocking).
**Why:** Session is a minimal Redis token (userId, tenantId, mfaSatisfied, stepUpSatisfiedAt, createdAt). Role names are not cached in the session.
**How to apply:** Never use req.session!.roles — it does not exist and will fail the typecheck.

### Drizzle inArray with roleNameEnum
Pass string literals directly — do NOT use `as unknown as string[]`. The enum overload matches
when values are the literal union type. Use: `inArray(rolesTable.name, ["role_a", "role_b"])`.
**Why:** PgEnumColumn's inArray overload requires `readonly (EnumValue | Placeholder)[]`, not `string[]`.

### Webhook signing secret: write-only invariant
The secretHash column is NEVER included in any SELECT. Use column-level select lists instead of
`select()` (which selects all columns) for all GET and PATCH responses on webhooks.
POST and PATCH-with-rotation return the raw signingSecret ONCE in the response body.
The DB CHECK `webhooks_https_url_ck` enforces https://, and the API validates before the INSERT.

### KEY stream events blocked from webhook subscriptions
KEY stream topics (bheka.key.rotated.v1, bheka.key.shredded.v1) are filtered out at webhook
creation and update time. The Set `KEY_STREAM_TOPICS` in webhooks.ts is the gateway-layer fence;
bheka-deliver owns the definitive filter downstream.

### Transparency notices: gateway is read-only for notice content
Notices are generated by bheka-notify/bheka-case reacting to events (CANON §5, §18).
The gateway exposes GET (list/detail) + acknowledge only. No POST /transparency-notices route
exists on the gateway — notice creation is an internal service operation.
