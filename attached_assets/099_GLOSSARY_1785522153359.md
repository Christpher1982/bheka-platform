## Visibility and evidence model

- **Tier 1 (Baseline)** — metadata-only telemetry (app/URL categories, session times,
  volume counts, typing cadence without content, file-operation counts). On by default.
- **Tier 2 (Elevated)** — trigger-based content capture. Off by default, activated by
  specific detection rules.
- **Tier 3 (Investigation)** — full content capture including keystrokes. Off by default,
  requires an open case, dual authorisation (two approvers, one of whom must be the
  Information Officer), a stated reason, a bounded time window, and an employee-facing
  transparency notice.
- **Dual authorisation** — the requirement that Tier 3 activation be approved by two
  named people, one of whom must be the Information Officer, before it can begin.
- **Transparency notice** — the disclosure given to an employee that their communications
  or activity may be or are being monitored, central to satisfying RICA section 6's
  "reasonable efforts to inform in advance" standard.
- **Crypto-shredding** — destroying a tenant's encryption key so that all of that
  tenant's data, including backups, becomes permanently unrecoverable; used as the
  technical mechanism for POPIA section 14 retention-limit compliance.
- **Envelope encryption** — the pattern in which Eride Vault decrypts only per-blob data
  encryption keys (DEKs), never the bulk encrypted payload itself (ADR-011).
- **Hash-chained evidence export** — a court-admissible evidence bundle with cryptographic
  chain-of-custody linking, designed to satisfy the authenticity and non-tampering
  conditions South African courts and CCMA commissioners look for.

## Key custody

- **Tier A (Eride-managed)** — Eride holds the tenant's key via AWS KMS and can decrypt
  through Vault policy; the default for SME customers.
- **Tier B (Customer-managed CMK)** — the customer holds their own key (their own KMS or
  Key Vault); Eride cannot decrypt. Target: banks, insurers, listed companies.
- **Tier C (Customer-hosted Vault)** — the entire Vault runs inside the customer's own
  estate; Eride cannot decrypt under any circumstance. Target: government, air-gapped, or
  SITA-adjacent environments.
- **DEK** — data encryption key; a per-blob, randomly generated AES-256-GCM key sealed to
  the tenant's public key via HPKE.
- **HPKE** — Hybrid Public Key Encryption, per RFC 9180; the mechanism by which DEKs are
  sealed to a tenant's public key.
- **X25519** — the elliptic-curve key-agreement algorithm used in Bheka's hybrid
  encryption scheme.
- **No global master key** — the architectural principle that every tenant has its own
  independent root key, so no single compromised key exposes more than one tenant.

## Technology and architecture terms

- **ETW** — Event Tracing for Windows; the user-mode telemetry mechanism used by the
  Windows agent in v1 (no kernel driver or minifilter).
- **eBPF / CO-RE** — extended Berkeley Packet Filter with Compile Once, Run Everywhere;
  the Linux telemetry mechanism used via `libbpf`/`aya`, avoiding an out-of-tree kernel
  module.
- **ESF** — Apple's Endpoint Security Framework; the macOS telemetry mechanism gated on a
  scarce, slow-to-obtain Apple entitlement (historically 8–13 months).
- **Network Extension** — the macOS content-filtering mechanism used in v1 that requires
  no Apple approval, ahead of ESF availability.
- **SQLCipher** — the encrypted SQLite variant used for the agent's local offline buffer.
- **RLS** — Row Level Security; the PostgreSQL mechanism enforcing tenant data isolation
  at the database layer.
- **UUIDv7** — the time-ordered UUID format used for all primary keys in the data model.
- **ClickHouse** — the columnar datastore used for high-volume endpoint telemetry events.
- **NATS JetStream** — the event bus / message streaming system used for internal service
  communication.
- **mTLS** — mutual TLS; required for all agent-to-backend and Vault communication.
- **OIDC** — OpenID Connect; the authentication protocol used for human (non-agent) API
  access.
- **WebAuthn step-up** — an additional authentication challenge required before viewing
  or approving Tier 3 evidence.
- **RFC 9457 problem+json** — the standardised error response format used across the
  Bheka API.
- **Update ring** — the phased rollout model for agent updates: Canary → Ring0 (1%) →
  Ring1 (10%) → Ring2 (50%) → Ring3 (100%), with a minimum soak time and automatic halt on
  crash-rate regression.
- **Channel File 291** — shorthand reference to the 2024 CrowdStrike incident used as the
  cautionary precedent for Bheka's ring-deployment and rollback discipline for detection
  content and agent updates.

## Service names

- **bheka-agent** — the Rust endpoint collector.
- **bheka-gateway** — the public REST API, authentication, and rate-limiting service.
- **bheka-ingest** — the service that receives encrypted agent telemetry batches and
  writes them to ClickHouse.
- **bheka-policy** — the service that runs detection rules, risk scoring, and tier
  escalation decisions.
- **bheka-case** — the investigations, approvals, and evidence-request service.
- **bheka-notify** — the service handling transparency notices and administrator alerts
  (including WhatsApp and email).
- **bheka-console** — the Next.js web user interface.
- **eride-vault** — the Rust key-custody and cryptographic policy-enforcement service.
- **bheka-updater** — the Rust agent update orchestration and ring-rollout service.

## Legal and regulatory terms

- **POPIA** — the Protection of Personal Information Act, 4 of 2013, South Africa's
  general data protection statute.
- **RICA** — the Regulation of Interception of Communications and Provision of
  Communication-Related Information Act, 70 of 2002.
- **ECT Act** — the Electronic Communications and Transactions Act, 25 of 2002.
- **Cybercrimes Act** — the Cybercrimes Act, 19 of 2020.
- **Joint Standard 2 of 2024** — the cybersecurity and cyber resilience standard jointly
  issued by the Prudential Authority and the Financial Sector Conduct Authority, effective
  1 June 2025.
- **DPSA directive** — the Department of Public Service and Administration's cloud
  computing directive requiring South African government data residency.
- **LRA** — the Labour Relations Act, governing dismissal fairness and CCMA procedure.
- **BCEA** — the Basic Conditions of Employment Act.
- **CCMA** — the Commission for Conciliation, Mediation and Arbitration, South Africa's
  primary labour dispute forum.
- **Information Regulator** — the statutory body responsible for enforcing POPIA (and
  PAIA), including registration of Information Officers and issuing infringement notices.
- **Information Officer (IO)** — the person within an organisation responsible for POPIA
  compliance, required to be registered with the Information Regulator before taking up
  duties.
- **Deputy Information Officer (DIO)** — a delegate of the Information Officer, also
  subject to registration.
- **Decryption key holder** — the RICA section 21 term for a person in possession of a
  decryption key who may be the subject of a decryption direction from a designated judge.
- **Decryption direction** — a RICA section 21 order compelling a decryption key holder to
  disclose a key or provide decryption assistance.
- **Cryptography provider registration** — the ECT Act Chapter V requirement to register
  with the Department of Communications and Digital Technologies before supplying a
  cryptography product or service in South Africa.
- **Section 71 (POPIA)** — the provision restricting decisions based solely on automated
  processing/profiling that have legal or substantial effect on a data subject.
- **Section 72 (POPIA)** — the provision governing cross-border transfer of personal
  information.
- **NDA** — non-disclosure agreement.
- **ADR** — Architecture Decision Record; the mechanism by which a Locked decision in
  CANON can be formally revisited and superseded.

## AI and model governance terms

- **Investigation copilot** — the generative-AI assistant inside `bheka-case` that drafts
  case summaries and suggests investigative leads, without ever recommending disciplinary
  action.
- **Risk score** — the explainable, per-user composite score derived from behavioural
  telemetry signals, decomposable into its contributing factors.
- **Bias testing / fairness audit** — the pre- and post-deployment process of testing a
  model for disparate impact across protected characteristics before and after production
  deployment.
- **Demographic parity difference** — a fairness metric measuring whether outcomes are
  proportionally similar across groups.
- **Disparate impact ratio** — a fairness metric, commonly benchmarked against the
  four-fifths (0.8) rule from US employment law, used as a reference point (not a South
  African legal standard) for evaluating adverse impact across groups.
- **Equalised odds difference** — a fairness metric measuring whether true and false
  positive rates are similar across groups.

## Document and process terms

- **Locked** — a document status marker meaning the decision will not change without a
  formal ADR.
- **Provisional** — a document status marker meaning this is the best current answer,

- **Open** — a document status marker meaning a known gap exists and the question is

- **Anti-drift rule** — the CANON section 14 rule that prose must reference schema files
