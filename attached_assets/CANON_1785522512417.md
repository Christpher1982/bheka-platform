## 2. Technology stack (Locked unless noted)

### Endpoint agent
- Language: **Rust** (edition 2021, MSRV 1.83).
- Windows telemetry: **ETW** (Event Tracing for Windows) user-mode consumers only in v1.
  NO kernel driver, NO minifilter in v1. Minifilter deferred to v2 for blocking.
- Linux telemetry: **eBPF with CO-RE** (compile once, run everywhere) via `libbpf` / `aya`.
  NO out-of-tree kernel module — this avoids Secure Boot MOK enrolment.
- macOS telemetry: **Network Extension content filter** in v1 (needs no Apple approval),
  **Endpoint Security Framework** in v1.5+ (gated on Apple entitlement approval).
- Agent local buffer: SQLite with SQLCipher, 30-day offline capacity.
- Agent crypto: hybrid. Agent holds ONLY the tenant public key (X25519). Per-blob random
  DEK (AES-256-GCM), DEK sealed to tenant public key via HPKE (RFC 9180).
  **The agent can never decrypt anything, including its own prior uploads.**

### Backend
- Runtime: **Node.js 22 LTS**, **TypeScript 5.7**, strict mode, ESM.
- HTTP framework: **Fastify 5**.
- Query layer: **Drizzle ORM** for typed queries, raw SQL migrations checked into git.
  No hidden migrations, no ORM-generated schema drift.
- Validation: **Zod** at every trust boundary. Zod schemas generate the OpenAPI document.
- Primary datastore: **PostgreSQL 16** (tenant metadata, cases, RBAC, policy, audit index).
- Telemetry datastore: **ClickHouse 24.x** (high-volume endpoint events).
- Event bus: **NATS JetStream**.
- Cache / rate limit / short-lived tokens: **Redis 7** (Valkey acceptable).
- Object storage: **S3-compatible**, AWS `af-south-1` (Cape Town) primary.
  Audit logs and sealed evidence use **S3 Object Lock in COMPLIANCE mode**.

### Eride Vault
- Language: **Rust** (not TypeScript). Rationale: smallest possible auditable attack surface,
  memory safety, shares the `bheka-crypto` crate with the agent so one implementation is
  reviewed once. This is ADR-003.
- Exposes gRPC over mTLS only. Never exposed to the public internet.
- Runs in a **separate cloud account / subscription** from the rest of the platform.
- KMS: **AWS KMS** in v1. Azure Key Vault Premium and Managed HSM supported for Tier B.
  Dedicated Managed HSM (~USD 3.20/hour, ~USD 2,336/month per cluster) deferred until a
  customer contractually funds it.

### Frontend
- **Next.js 15** (App Router), TypeScript, Tailwind CSS 4, shadcn/ui, TanStack Query.
- Server Components for reads, Server Actions prohibited for any privileged operation —
  privileged operations go through the versioned REST API so they are auditable.

### Infrastructure
- Containers, **Terraform** for IaC, **GitHub Actions** for CI/CD.
- Observability: **OpenTelemetry** traces/metrics/logs, Grafana stack.
- On-prem/air-gap: `.ova` appliance + Docker Compose + Helm chart.

## 4. The three visibility tiers (Locked)

| Tier | Name | What is collected | Default |
|---|---|---|---|
| 1 | **Baseline** | Metadata only. App/URL categories, session times, volume counts, typing rhythm (cadence, no content), file operation counts. No content of any kind. | On |
| 2 | **Elevated** | Trigger-based. Activated by a policy rule for a bounded window. File names, full URLs, USB device identifiers, clipboard event metadata, periodic low-rate screenshots. | Off, rule-activated |
| 3 | **Investigation** | Full content capture. Keystroke content, full screen recording, clipboard content, file content hashes and optional copies. | Off, requires dual authorisation |

**Keystroke logging: supported, Tier 3 only, off by default, password and credential fields
masked at agent level before encryption, no hidden agent mode exists.** Tier 1 collects
keystroke *metadata* only (rhythm, WPM, no content).

Tier 3 activation requires: an open case record, two distinct approvers (one must hold the
Information Officer role), a stated reason, a bounded time window, and it emits a
transparency notice per section 5.

## 5. Permanent product refusals (Locked, non-negotiable)

Bheka will never ship:
1. A hidden, invisible, or disguised agent. The agent is always discoverable by the user.
2. Webcam capture.
3. Ambient microphone capture.
4. Installation on employee personal devices (BYOD is out of scope, permanently).
5. Remote desktop takeover or remote control of an employee machine.
6. Emotion, sentiment, or "loyalty" scoring of individuals.
7. Automated adverse employment decisions. Bheka produces evidence; humans decide.
8. Silent Tier 3 activation. Every Tier 3 activation generates a record the data subject can see.

These are stated publicly and contractually. They are the product's positioning.

## 6. Three key custody tiers (Locked) — ADR-004

| Tier | Name | Root key location | Can Eride decrypt? | Target buyer |
|---|---|---|---|---|
| A | Eride-managed | Eride's AWS KMS, per-tenant root, no shared master | Yes, via Vault policy | SME, default |
| B | Customer-managed (CMK) | Customer's own AWS KMS / Azure Key Vault | **No** | Banks, insurers, listed companies |
| C | Customer-hosted Vault | Entirely inside customer estate | **No** | Government, air-gapped, SITA-adjacent |

**There is no global master key.** Per-tenant root keys with no common ancestor. A single
key compromise is capped at one tenant.

Envelope encryption rule (Locked, ADR-011): **the Vault decrypts data encryption keys only,
never bulk payloads.** The requesting service decrypts the payload in memory with a
short-lived DEK it never persists. Routing 400 MB screen recordings through the Vault is
prohibited.

Crypto-shredding: destroying a tenant root key renders all that tenant's evidence
permanently unrecoverable, including in backups. This is the POPIA s14 retention mechanism.

## 7. Legal framework (cite these, do not invent others)

- **POPIA** (Protection of Personal Information Act 4 of 2013) — lawful basis, s14 retention
  limits, s19 security safeguards, s22 breach notification, Information Officer role.
- **RICA** (Act 70 of 2002) — s21 decryption directions to a "decryption key holder";
  non-compliance is a criminal offence. This is precisely why Tier B and C exist.
  Note: parts of RICA were declared unconstitutional in 2021 and amended; requires
  attorney confirmation of current text. Mark as Provisional.
- **ECT Act** (Act 25 of 2002) Chapter V — cryptography provider registration with the
  Department. Supplying cryptography products in SA without registration is an offence.
  Application must be filed in week 1.
- **Cybercrimes Act** (Act 19 of 2020) — s29 search warrants, s39 disclosure prohibitions,
  technical assistance obligations.
- **Joint Standard 2 of 2024** (Prudential Authority / FSCA IT governance and risk) —
  commenced 1 June 2025, drives the financial-services buyer.
- **DPSA directive** — government data must reside in South Africa.
- Labour context: LRA, BCEA, and the requirement that monitoring evidence be procedurally
  fair to be admissible in a CCMA or Labour Court proceeding.

## 9. API standard (Locked)

- Base path `/v1`. Versioning in the path. No breaking changes within a major version.
- Errors: **RFC 9457 `application/problem+json`**.
- Auth: OIDC bearer tokens for humans; mTLS + per-agent certificate for agents.
- Step-up: **WebAuthn** required before any Tier 3 evidence view or approval.
- Idempotency: `Idempotency-Key` header required on all POST that create resources.
- Pagination: cursor-based, `?cursor=&limit=`, max limit 200.
- Rate limits returned via `RateLimit-*` headers (RFC 9331 draft style).
- Every privileged endpoint writes to `audit_log` before returning.

## 11. Packaging and distribution (Locked)

| Target | Artifact | Signing |
|---|---|---|
| Windows | `.msi` canonical, thin `.exe` bootstrapper | EV code signing cert on FIPS hardware token (SSL.com ~USD 349 + USD 379 token) |
| Intune | `.intunewin` | inherits MSI signature |
| macOS | `.pkg` | Developer ID Installer, notarized, stapled |
| macOS MDM | signed `.mobileconfig` | pre-approves extensions silently |
| Linux | `.deb` / `.rpm` from private GPG-signed aptly / createrepo repos | GPG |
| On-prem | `.ova` + Docker Compose + Helm chart | GPG-signed checksums |

- **MSIX is prohibited** — it cannot contain drivers and forecloses v2.
- **One generic signed installer per platform.** Tenant identity is injected at install
  time via UPPERCASE MSI properties listed in `SecureCustomProperties`
  (`TENANT_ID`, `ENROLMENT_TOKEN`, `SERVER_URL`, `TIER`). Never per-tenant builds —
  Apple caps notarization at 75/day.
- Platform order: **Windows → Linux → macOS** (Apple ESF entitlement waits are reported
  at 8–13 months with no status visibility).
- Update rings: N-1/N-2 model modelled on the CrowdStrike Channel File 291 RCA lessons.
  Canary (Eride internal) → Ring 0 (1%) → Ring 1 (10%) → Ring 2 (50%) → Ring 3 (100%),
  minimum 24h soak per ring, automatic halt on crash-rate regression.

## 14. Anti-drift rule (MANDATORY)
