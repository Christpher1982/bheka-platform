# Changelog

All notable changes to the Bheka Engineering Blueprint are recorded here.

This blueprint follows a `MAJOR.MINOR` scheme. The major version increments when a change
invalidates existing implementation work. The minor version increments for refinements,
added documents, and status changes.

Format loosely follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

---

## [1.0] — 2026-07-31

First complete blueprint. Nothing has been built against it yet.

### Added

**Canon and governance**
- `CANON.md` establishing authoritative decisions for stack, naming, tiers, custody,
  legal framework and packaging
- `docs/000_PROJECT_CONSTITUTION.md` with decision rights and the eight permanent product
  refusals
- Document status marker system (Locked / Provisional / Open)
- Anti-drift rule: prose may not restate a schema

**Architecture**
- Nine-service architecture: `bheka-agent`, `bheka-gateway`, `bheka-ingest`, `bheka-policy`,
  `bheka-case`, `bheka-notify`, `bheka-console`, `eride-vault`, `bheka-updater`
- Rust endpoint agent, TypeScript/Node backend, Rust Eride Vault
- PostgreSQL 16 for state, ClickHouse for telemetry, NATS JetStream for events
- Full threat model across seven trust boundaries

**Cryptography and custody**
- Three key custody tiers (Eride-managed, customer-managed, customer-hosted)
- Per-tenant root keys with no global master key
- Hybrid HPKE agent encryption — the agent holds only a public key and can never decrypt
- Envelope encryption where the Vault unwraps data encryption keys only and never touches
  bulk payloads
- Crypto-shredding as the POPIA section 14 retention mechanism

**Product model**
- Three visibility tiers (Baseline metadata-only, Elevated trigger-based, Investigation)
- Keystroke logging specified as Tier 3 only, off by default, credential fields masked at
  the agent, with no hidden agent mode
- Employee-facing transparency layer: the monitored person and the Information Officer see
  records of Tier 3 access
- Africa module: load-shedding resilience, 30-day offline buffering, low-bandwidth mode,
  five-language notices, WhatsApp alerting, ZAR billing

**Packaging and distribution**
- Signed `.msi` as the canonical Windows artifact, MSIX prohibited
- Notarized and stapled `.pkg` plus signed `.mobileconfig` for macOS
- GPG-signed `.deb` and `.rpm` from private repositories
- `.intunewin` for Intune, `.ova` plus Compose and Helm for on-premises
- One generic installer per platform with tenant configuration injected at install time
- N-1/N-2 update ring model with automatic halt on crash-rate regression

**Machine-readable schemas**
- PostgreSQL DDL for all canonical tables with row-level security
- ClickHouse DDL with MergeTree engines, partitioning and TTL
- OpenAPI 3.1 document
- JSON Schema per event topic
- Policy rule DSL schema with examples

**Standards, ADRs and guides**
- 16 architecture decision records
- 5 engineering standards
- 10 build guides
- 9 operational runbooks
- 8 document templates
- v1 backlog, sprint plan, local development setup, AI assistant brief

### Known limitations of v1.0

These are stated plainly rather than buried.

- **Not validated with customers.** The fifteen discovery interviews have not happened.
  The detection rule library, the pricing bands and the ideal customer profile are
  hypotheses, not findings.
- **Not reviewed by an attorney.** Every legal section is marked Provisional. The RICA
  section 21 exposure analysis in particular needs professional confirmation, including
  confirmation of the current statutory text following the 2021 constitutional challenge
  and subsequent amendments.
- **macOS is underspecified** relative to Windows, because the Apple Endpoint Security
  Framework entitlement has not been applied for or granted.
- **No performance validation.** Throughput, agent resource ceilings and ingestion capacity
  figures are engineering estimates, not measurements.
- **No external threat model review.** The threat model in `docs/003_THREAT_MODEL.md` was
  written by the same people who designed the system, which is a known weakness.
- **Enterprise security review artifacts are absent.** CAIQ, SIG Lite, subprocessor list and
  penetration test summary are out of scope for v1.0.
